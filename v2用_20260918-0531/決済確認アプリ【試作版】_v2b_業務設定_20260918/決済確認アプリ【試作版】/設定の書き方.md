# settings.json の書き方 ―「業務設定」の直し方

画面のレイアウトは固定です。**どの CSV の、どの列を、どう切り出して、何でつなぎ、どの枠に出すか**は、settings.json の先頭にある `"業務設定"` だけで決まります。本体（src）にも画面（web）にも触りません。
JSON にはコメントを書けないので、この紙を見ながら直してください。

直したあとは、アプリを起動するか `tools\ReaderDataViewer.cmd -ValidateOnly` を実行します。そろっていない箇所があれば、どこが合っていないかを日本語で出します（例:「表「受付け」が 業務設定.入力ファイル にありません」）。

## 全体の形

```json
"業務設定": {
  "入力ファイル": { ... },        ← 1. 読む CSV と、その行を識別する列
  "切り出し": { ... },            ← 2. CSV の列から作る列（式）
  "つなぎ方": [ ... ],            ← 3. 表と表をつなぐ列
  "支払済の条件": [ ... ],        ← 4. 「支払済」にする条件（全部そろったとき）
  "台帳の1件を決める列": [ ... ], ← 5. 統合台帳の 1 行を決める列
  "検索に使う列": [ ... ],        ← 6. 検索窓で引ける列
  "台帳に追加で残す列": [ ... ],  ← 7. 画面に出さなくても台帳に残したい列
  "削除の条件": { ... },          ← 8. 削除用 CSV との突き合わせ
  "画面": { ... }                 ← 9. 画面の枠のラベルと列
}
```

列はどこでも **`表の名前.列名`** で書きます（例 `決済.オーダーID`）。表の名前は「入力ファイル」で自分が付けた名前、列名は CSV の 1 行目の見出し、または「切り出し」で作った名前です。
前後の空白・全角半角・大文字小文字の違いは読み込み時に吸収されますが、**列名そのものは同じ文字で書いてください**（推測はしません）。

## 1. 入力ファイル

```json
"入力ファイル": {
  "取引":   { "ファイル名": "01_取引データ.csv", "一致": "前方一致", "識別する列": "【共通】取引ID" },
  "決済":   { "ファイル名": "02_決済データ.csv", "一致": "前方一致", "識別する列": "オーダーID" },
  "受付":   { "ファイル名": "03_受付データ.csv", "一致": "前方一致", "識別する列": "受付時＿識別番号" },
  "削除用": { "ファイル名": "04_削除用_手続完了.csv", "一致": "前方一致", "識別する列": ["識別番号", "受付番号"] }
}
```

| 項目 | 意味 |
|---|---|
| 表の名前（`取引` など） | 設定の中で列を指すときの呼び名。日本語で可。`.` と空白は使えない |
| `ファイル名` | data フォルダー内のファイル名 |
| `一致` | `前方一致`（既定。その名前で始まる一番新しいファイルを読む。例 `01_取引データ_20260918.csv`）／`全部一致`（同じ名前。前後の空白・全角半角・大文字小文字の違いは吸収） |
| `識別する列` | その CSV で 1 行を識別する列。2 列なら配列。同じ値の行が複数あると、その行は除外されてログに残ります |

- 文字コードは、ファイル先頭の BOM → UTF-8 → Shift_JIS の順に自動で判定します。区切り（カンマ／タブ）も見出し行から判定します。
- ファイル名と一致方法は、アプリの「設定」画面からも変えられます（設定画面が書き戻すのはこの 2 つと、場所・検索・監視対象だけ）。

## 2. 切り出し

```json
"切り出し": {
  "決済.識別番号": "regexExtract(決済.オーダーID, '[A-Z]{2}[0-9]{8}[A-Z]{2}')",
  "決済.受付拠点": "splitPart(決済.備考2, '/', 4)",
  "決済.利用者氏名": "splitPart(決済.氏名, '-', 1)"
}
```

左が **作る列の名前**（`表.新しい列名`）、右が **式** です。式の中では同じ表の列だけを使えます。式は 3 種類。**位置の番号は 0 始まり**です。

| 式 | 意味 | 例 |
|---|---|---|
| `regexExtract(列, '正規表現')` | 正規表現に最初に一致した部分を取り出す。一致しない行は除外され、理由がログに残る | `regexExtract(決済.オーダーID, '[A-Z]{2}[0-9]{8}[A-Z]{2}')` → `AB10000001CA` |
| `splitPart(列, '区切り', 位置)` | 区切りで分けた 位置 番目（0 始まり）。無い・空なら空欄（行は落とさない） | `splitPart(決済.備考2, '/', 4)` … `乙ウエXB26-10001/19800207/経路2//拠点2/区分B/利用者1` の `拠点2` |
| `substring(列, 開始, 長さ)` | 開始位置（0 始まり）から長さぶん | `substring(取引.【共通】取引日時, 0, 10)` |

- 全角の英数字・ハイフン、前後の空白は、式に渡す前に半角へそろえます。
- 受付番号のように接頭辞や桁が揺れる値は、揺れを許す正規表現にします。いまの設定の例:
  `(?:[\p{IsCJKUnifiedIdeographs}\p{IsKatakana}\p{IsHiragana}]{1,5})?[A-Z]{1,4}[0-9]{1,4}-[0-9]{1,10}`
  （局名 1〜5 字は省略可、英 1〜4 字、数 1〜4 桁、`-`、連番 1〜10 桁）
- JSON の中では `\` を `\\` と書きます（上の例は JSON では `\\p{...}`）。
- 作る列の名前に半角の `( ) , + - * /` と空白は使えません（全角の `（）` は可）。

## 3. つなぎ方

```json
"つなぎ方": [
  { "左": "決済.識別番号", "右": "取引.識別番号", "残す行": "両方にある行" },
  { "左": "決済.識別番号", "右": "受付.識別番号", "残す行": "左は全部" }
]
```

上から順につなぎます。1 行目の左の表が土台です（この例では決済）。2 行目以降の左は、既につないだ表の列を書きます。右は、まだつないでいない表の列です。

| `残す行` | 意味 |
|---|---|
| `両方にある行` | 左右とも値のある行だけ残す（取引と決済の突合） |
| `左は全部` | 左の行は全部残し、右に無ければ空欄（受付情報を付ける） |
| `両方全部` | 左右どちらの行も残す |

値の比較は文字どおりの一致です。「切り出し」で作った列どうしをつなぐと、全角半角・空白の揺れは吸収済みになります。

## 4. 支払済の条件

```json
"支払済の条件": [
  { "列": "取引.【共通】ステータス", "値": "支払済" },
  { "列": "決済.決済ステータス",   "値": "決済済" }
]
```

書いた条件が **全部そろった行**が「支払済」です。比較は全角半角・大文字小文字・前後の空白の違いを吸収します。ここに書いた列は、自動で台帳にも残ります。

## 5〜7. 台帳の列

```json
"台帳の1件を決める列": ["決済.識別番号", "決済.受付番号（照合用）"],
"検索に使う列":       ["決済.識別番号", "決済.受付番号（照合用）", "受付.受付番号（照合用）"],
"台帳に追加で残す列": ["取引.【共通】取引ID", "決済.オーダーID", "決済.決済金額", "取引.【共通】ステータス", "取引.【共通】取引結果"]
```

- `台帳の1件を決める列`: 統合台帳の 1 行を決める列。同じ組の行が 2 つあると、その行は除外されてログに残ります。
- `検索に使う列`: 検索窓に入れた値と一致させる列。全角半角・大文字小文字は無視して一致します。
- 台帳に残る列は、**画面・候補一覧・識別・検索・削除・支払済の条件・帳票出力の初期項目に書いた列から自動で決まります**。それ以外で台帳（Excel）に残したい列は `台帳に追加で残す列` に書きます。同じ列を何か所にも書く必要はありません。
- 検索窓に入る値の形（正規表現）は `業務設定` の外の `"search": { "pattern": ... }` です（設定画面の「番号の形式」と同じもの）。

## 8. 削除の条件

```json
"削除の条件": {
  "ファイル": "削除用",
  "一致させる列": [
    { "台帳の列": "決済.識別番号", "削除用の列": "削除用.識別番号（照合用）" },
    { "台帳の列": ["受付.受付番号（照合用）", "決済.受付番号（照合用）"], "削除用の列": "削除用.受付番号（照合用）" }
  ]
}
```

`ファイル` は入力ファイルのうち、つなぎ方に出てこない表（削除用の一覧）。`一致させる列` の全部が一致し、かつ台帳の確認状態が「確認済」（送信済み）の行が削除されます。`台帳の列` を配列にすると、**どれか 1 つが一致すれば**その列は一致とみなします（受付番号が 02 側・03 側どちらの採番でもよい、という書き方）。

## 9. 画面

```json
"画面": {
  "検索欄のラベル": "識別番号／受付番号",
  "利用者情報": { "枠の名前": "利用者情報", "行": [
    { "ラベル": "利用者ID",   "列": "決済.利用者ID" },
    { "ラベル": "利用者氏名", "列": "決済.利用者氏名" },
    { "ラベル": "利用者区分", "列": "決済.利用者区分" } ] },
  "受付情報": { "枠の名前": "受付情報", "行": [
    { "ラベル": "申込日", "列": "受付.申込日", "CSVの日付": "yyyyMMdd", "画面の日付": "yyyy/MM/dd" },
    ...（最大 7 行）... ] },
  "意見欄":       { "枠の名前": "意見欄", "列": "受付.意見欄" },
  "変更後の計画": { "枠の名前": "変更後の計画", "列": "受付.変更後の計画" },
  "決済状況":     { "枠の名前": "決済状況", "支払済の表示": "支払済", "未決済の表示": "未決済" },
  "候補一覧": [
    { "見出し": "受付番号", "列": "決済.受付番号（照合用）" },
    ...（最大 4 列。右端の決済状況の列は自動で付きます）... ],
  "帳票出力の初期項目": ["受付.受付時＿識別番号", "決済.受付番号", ..., "確認状態", ...]
}
```

| 枠 | 行数 | 画面の位置 |
|---|---|---|
| `利用者情報` | 最大 3 行 | 左上の枠 |
| `受付情報` | 最大 7 行 | 右上の枠 |
| `意見欄` `変更後の計画` | 各 1 | 下の 2 つの文章枠 |
| `決済状況` | ― | 一番下の帯 |
| `候補一覧` | 最大 4 列 | 検索で複数当たったときの一覧（左端の #、右端の決済状況と確認の列は固定） |

- `ラベル` / `枠の名前` / `見出し` はそのまま画面に出ます。行を書かなかった枠の行は表示されません。
- `CSVの日付` は CSV の日付の書き方、`画面の日付` は画面での書き方です。読み込み時は `yyyyMMdd` / `yyyy/M/d` / `yyyy-MM-dd` などの違いも受け付けます。
- 決済状況の帯は、検索前「未検索」、形式が違う「入力内容を確認してください」、台帳に無い「対象データが見つかりません」、案件があって条件がそろわない「未決済の表示」、そろった「支払済の表示」です。
- `帳票出力の初期項目` は「帳票出力」画面で最初から選ばれている列です。`確認状態` はアプリが付ける確認済／未確認の列です。

## 直した設定の確かめ方

1. `tools\ReaderDataViewer.cmd -ValidateOnly` … 設定と CSV の整合を確認（ファイルは書きません）
2. `tools\ReaderDataViewer.cmd -RunUpdate -Output 結果.json` … 統合台帳を作った結果を JSON へ出力（共有台帳には書きません）
3. アプリを起動 … 起動時に CSV を読み、結果をステータスバーに出します。読めなかったときはダイアログに理由が出ます。

`業務設定` を変えると台帳の「業務定義」が変わるため、前の設定で作った統合台帳はそのまま使えません（新しい台帳を作るか、`tools\Migrate-Ledger.ps1` で移行）。ファイル名と一致方法、画面のラベルと見出し、支払済／未決済の表示は定義に含まれないので、変えても台帳はそのまま使えます。
