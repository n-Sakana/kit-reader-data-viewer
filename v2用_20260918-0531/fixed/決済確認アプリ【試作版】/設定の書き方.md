# settings.json の書き方（本番で列や形式が変わったとき）

画面のレイアウトは固定です。**どの CSV の、どの列を、どう切り出して、どの枠に出すか**は settings.json だけで決まります。
JSON にはコメントを書けないので、この紙を見ながら直してください。
直したあとは、アプリを起動するか `tools\ReaderDataViewer.cmd -ValidateOnly` を実行すると、そろっていない箇所を日本語で指摘します。

## 1. 入力ファイル（data.tables）

```json
"TXN": {
  "label": "①取引データ",
  "file": "01_取引データ.csv",
  "fileMatch": "exact",
  "key": "【共通】取引ID"
}
```

| 項目 | 意味 |
|---|---|
| `label` | 画面や案内に出す表の名前 |
| `file` | data フォルダー内のファイル名。`fileMatch` が `"exact"` なら同じ名前（前後の空白・全角半角・大文字小文字の違いは吸収）、`"prefix"` ならその名前で始まる一番新しいファイル（例 `01_取引データ_20260918.csv`） |
| `key` | 行を識別する列。CSV の 1 行目の列名と同じ文字。2 列で識別するなら `["識別番号", "受付番号"]` のように配列 |
| `encoding` / `delimiter` | 省略可。文字コードは BOM → 設定 → UTF-8 → Shift_JIS の順に自動判定、区切りは見出し行から自動判定（カンマ／タブ） |

ファイル名と一致方法は、アプリの「設定」画面からも変えられます（この項目だけ settings.json へ書き戻します）。

## 2. 列の書き方

設定の中で列を指す書き方は、どこでも **`表ID.列名`** です。
- 入力表の列: `PAY.備考2`（PAY は data.tables の ID、備考2 は CSV の見出し）
- 手順で作った列: `PAY.受付番号照合用`（calculate の `output` が PAY、`column` が 受付番号照合用）
- 結合結果の列: 結合しても列名は変わりません（`PAIRED` の中でも `TXN.【共通】ステータス` のまま）

**列を 1 つ足す／変えるとき、そろえる場所は次の 5 か所です。**
1. `data.tables.<ID>.key`（入力表の識別列）
2. `data.jobs[].steps[]` の `keys` / `expression` / `where.column`（つなぐ列・切り出す元の列）
3. `data.ledger.identity`（台帳の行を識別する列）と `data.ledger.search.columns`（検索に使う列）
4. `data.ledger.columns.source`（台帳に保存する列。画面に出す列・検索する列・識別する列は必ずここにも並べる）
5. `screen.bindings` / `screen.candidates` の `field`（画面に出す列）
6. `data.labels`（手順に出てくる名前の画面名。新しい列や中間結果には画面名が要ります）

## 3. 切り出しの式（calculate の expression）

3 種類あります。**位置の番号は 0 始まり**です。

| 式 | 意味 | 例 |
|---|---|---|
| `regexExtract(列, '正規表現')` | 正規表現に最初に一致した部分を取り出す。一致しない行は除外され、理由がログに残る | `regexExtract(PAY.オーダーID, '[A-Z]{2}[0-9]{8}[A-Z]{2}')` → `AB10000001CA` |
| `splitPart(列, '区切り', 位置)` | 区切りで分けた 位置 番目（0 始まり）。無い・空なら空欄（行は落とさない） | `splitPart(PAY.備考2, '/', 4)` → `乙ウエXB26-10001/19800207/経路2//拠点2/区分B/利用者1` の `拠点2` |
| `substring(列, 開始, 長さ)` | 開始位置（0 始まり）から長さぶん | `substring(TXN.【共通】取引日時, 0, 10)` → `2026/4/2 2` |

- 全角の英数字・ハイフン、前後の空白は、式に渡す前に半角へそろえます。
- 受付番号のように接頭辞や桁が揺れる値は、揺れを許す正規表現にします。いまの設定の例:
  `(?:[\p{IsCJKUnifiedIdeographs}\p{IsKatakana}\p{IsHiragana}]{1,5})?[A-Z]{1,4}[0-9]{1,4}-[0-9]{1,10}`
  （局名 1〜5 字は省略可、英 1〜4 字、数 1〜4 桁、`-`、連番 1〜10 桁）
- JSON の中では `\` を `\\` と書きます（上の例は JSON では `\\p{...}`）。

## 4. つなぐキー（join / merge / extract の keys）

```json
{ "operation": "join", "target1": "PAIRED", "target2": "APP",
  "keys": ["PAY.識別番号照合用", "APP.識別番号照合用"], "condition": "left", "output": "INTEGRATED" }
```
- `keys` は `[左の列, 右の列]`。2 列の組なら `[["PAY.識別番号照合用", "APP.受付番号照合用"], ["DEL.識別番号照合用", "DEL.受付番号照合用"]]`。
- `condition`: `match`（両方にある行だけ）／`left`（左は全部残す）／`full`（両方残す）。
- 値の比較は文字どおりの一致です（式で切り出した列どうしをつなぐと、全角半角・空白の揺れは吸収済みになります）。

## 5. 画面の枠と一覧の見出し（screen）

```json
"screen": {
  "bindings": {
    "userId": { "label": "利用者ID", "field": "PAY.利用者ID", "empty": "" },
    "applicationDate": { "label": "申込日", "field": "APP.申込日", "empty": "",
      "format": { "kind": "date", "from": "yyyyMMdd", "to": "yyyy/MM/dd" } }
  },
  "judgments": { "paymentStatus": { "label": "決済状況", ... } },
  "candidates": { "applicationNumber": { "header": "受付番号", "value": { "field": "PAY.受付番号照合用", "empty": "" } } }
}
```

| 枠の ID | 画面の位置 |
|---|---|
| `userId` `userName` `userCategory` | 利用者情報の 3 行 |
| `applicationDate` `applicationNumber` `cardNumber` `applicantName` `birthDate` `qualification` `office` | 受付情報の 7 行 |
| `remarks` `plan` | 下の 2 つの文章枠（`label` は枠の見出しになります） |
| `judgments.paymentStatus` | 決済状況の帯（`label` は帯の左の見出し） |
| `candidates.*` | 候補一覧の列（`header` は列見出し） |

- `label` / `header` を書かなければ、いまの文言のままです。
- `field` に書く列は data.ledger.columns.source に並んでいる列だけです。
- `format` は日付の表示だけに使います（`from` は CSV の書き方、`to` は画面の書き方）。読み込み時は `yyyyMMdd` / `yyyy/M/d` / `yyyy-MM-dd` などの違いも受け付けます。

## 6. 決済状況の判定（screen.judgments.paymentStatus）

`PAIRED.決済確認済` が `支払済` なら「支払済」、空なら「未決済」です。
`支払済` を入れる条件は data.jobs の update-ledger にあります（取引データの `【共通】ステータス` が `支払済`、かつ決済データの `決済ステータス` が `決済済`）。
文言を変えるときは `results` の `text`、条件を変えるときは `where` の `value` を直します。`where` の比較は全角半角・大文字小文字・前後の空白の違いを吸収します。

## 7. 直した設定の確かめ方

1. `tools\ReaderDataViewer.cmd -ValidateOnly` … 設定と CSV の整合を確認（ファイルは書きません）
2. `tools\ReaderDataViewer.cmd -RunUpdate -Output 結果.json` … 統合台帳を作った結果を JSON へ出力（共有台帳には書きません）
3. アプリを起動 … 起動時に CSV を読み、結果をステータスバーに出します。読めなかったときはダイアログに理由が出ます。

settings.json の data 以下を変えると台帳の「業務定義」が変わるため、前の設定で作った統合台帳はそのまま使えません（新しい台帳を作るか、`tools\Migrate-Ledger.ps1` で移行）。
