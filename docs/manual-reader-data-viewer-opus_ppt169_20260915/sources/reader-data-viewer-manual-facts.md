## 1. 何をするアプリか

| 事実 | 出典 |
|---|---|
| CSV / XLSX を表として読み、結合・集計・抽出等から作った共有台帳を検索し、行ごとに確認状態を付けて送信する Windows アプリ。業務の流れは設定済みの一般操作を組み合わせて表す。自由なプログラム実行やあらゆる業務の自動化は約束しない | `README.md:7` |

## 5. 送信・共有の仕組み

| 事実 | 出典 |
|---|---|
| 状態ボタンの操作は、まずその Windows ユーザーのローカル未送信へ保存。送信して初めて共有台帳へ反映。未確認へ戻した値も送れる。閉じても未送信は残るが別 PC へは移らない | `README.md:894` |
| マージと送信は同じ共有ロック。ロック後に最新台帳を読み直す。送信は内容の指紋と変更前の状態を照合し、別の人の変更を黙って上書きしない。同じ値の再送は二重計上しない | `README.md:896` |
| 送信の順: ロック取得 → 最新台帳の読み直し → 識別キー・内容の SHA-256・変更前の共有状態を照合 → 反映 → 変更通知 → 反映済みのローカル変更を取り除く | `docs/shared-ledger.md:31-39` |
| 競合一覧からの破棄はローカル未送信だけが対象。破棄は追加確認とバックアップ付き。強制上書きは無い | `docs/shared-ledger.md:41` |
| 他 PC の変更は `.version`・更新時刻・サイズで検知し、内容が違えば案内と切替の確認を出す。状態だけ違うときは確認なしに最新へ切り替える | `docs/shared-ledger.md:49` |
| OneDrive 等の同期コピー、Excel での同時編集は対象外 | `README.md:354`, `docs/shared-ledger.md:65-67` |
| 2026-09-09 に WIN-DESKTOP と WIN-NOTE から試験用共有（Samba 4.23.6、SMB 3.1.1）へ同時送信を実機で試験 | `docs/shared-ledger.md:5-11` |
| CSV 出力はこの PC に見えている台帳と未送信の状態。他 PC の未送信は含まない。新規 CSV のみ | `README.md:964` |
| 設定の検査: `-ValidateOnly`（設定・入力・ジョブの接続）と `-RunUpdate`（更新ジョブを実行して結果 JSON。共有台帳・ロック・未送信には書かない） | `README.md:296-338` |
| 設定画面の保存は paths / search / watch を作り直し、その部分のコメントは消える。ほかの部分とコメントは残る | `README.md:948`, `docs/settings.md:109` |

## 7. 撮っていないもの・確かめていないもの

- 自動読み取り（メモ帳などの欄から値を読んで検索し、処理済へ進む流れ）の実演。ノートの Windows 11 メモ帳は前回の内容を復元しうるため、撮影に使わなかった。仕組みは設定・README・コードの記述から書いた
- 「画面から選ぶ」の操作、「送信できなかったレコード」「データを読めません」「台帳が空くのを待機中」の実画面。文言は `src/Rdv3Text.cs` から
- 送信の直後に表示がどうなるか（撮影では［クリア］してから送信した。README は「送信後もそれまで表示していた識別値のレコードを最新台帳から探して表示し続けます」と書いている: `README.md:358`）
- 候補一覧の［キャンセル］の結果（コード上は何も表示しない: `src/Rdv3App.cs:777-783` の `picked >= 0` の条件）
- 複数 PC での動作（`docs/shared-ledger.md` の 2026-09-09 の試験記録を引いただけで、この撮影では 1 台）
- 固定版（reader-data-viewer-semifixed）の画面。この説明書は `kit/reader-data-viewer`（従来版）だけを対象にした
- 操作ログの「更新 N 件」が何を数えた値か。作成時は 80 件、1 行だけ中身が変わった更新では 81 件で、処理ログ `apply` の `updated` と同じ値だった（`capture-rig/app-log/`）。台帳で中身が変わった行の数とは一致しない。この説明書ではこの数を使っていない
- 通知が状態欄の時計の欄に出て、次の時計の更新で上書きされる見え方が、意図したものか。測ったのは「見つかりません」だけで、54ms で表示され 939ms で時計に戻った。`web/app.js:504` は通知を状態欄の 3 番目（無ければ最後）へ書き、このサンプル設定では 3 番目が時計（撮影時の表示 `08:37:09` など）
